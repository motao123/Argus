## 三、功能实测记录

### 3.1 服务监控（HTTP/TCP/Ping）
- 创建 3 个探测任务（argus-http 自探测 / bad-http 坏端口 / ssh-tcp 未开端口）
- 实测：HTTP 200 → up=True；坏端口 → up=False；延迟与可用率统计正常
- 今日可用率聚合正确（分钟级桶 + 累加）

### 3.2 文件管理器
- 列目录 62 项（/tmp）、写 18 字节、读回内容一致（EOF/Size 正确）、删除成功

### 3.3 多渠道通知
- 本地模拟 bark 端点 + webhook 端点
- 报警触发时双渠道同时收到：bark 收到 URL 编码的标题/内容，webhook 收到 JSON 模板

### 3.4 PAT 权限体系
- 创建 `argus:server:read` 只读令牌 → 读放行、写/exec 全部 403
- 吊销后立即 401

### 3.5 多用户隔离
- admin 创建普通用户 alice → alice 登录后服务器列表为空（owner 过滤）
- alice 尝试创建用户 → 403
- 删除用户联动删除名下服务器

### 3.6 WebSocket 实时推送
- 前端 2s 周期接收快照（浏览器实测在线 1/1，CPU/内存/网络实时更新）

### 3.7 网页终端
- Node WS 客户端模拟浏览器：打开会话 → 发送 `echo term-ok` → 收到回显输出
- 完整链路：浏览器 WS → Server → Agent → shell → 反向回传

## 五、已知限制（后续迭代）

1. **GeoIP**：依赖 mmdb 数据库（需从 GitHub 下载，当前网络不可达），整合版暂未启用，agent 已上报 IP 字段，接口预留
2. **主题市场 / 插件系统**（komari goja 沙箱）：体量大，列入后续迭代
3. **DDNS / NAT 内网穿透**（nezha）：需要公网环境验证，接口设计完成未实现
4. **i18n 多语言**：前端已预留，默认 zh-CN
5. **Agent 终端无 PTY**：简化实现（管道），复杂交互（vim/top）体验受限，后续可换 creack/pty

## 六、结论

整合项目已覆盖 komari + nezha 生态的核心能力：实时监控、历史指标、服务监控、
终端、文件管理、任务、多渠道告警、多用户、PAT 权限、现代化仪表盘。
后端 32 项回归全通过，前端 8 个页面浏览器实测正常，无逻辑冲突与运行异常。
